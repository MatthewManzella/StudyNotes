CTE Basics — WITH

A named, temporary result set defined with WITH, referenced like a table below it. Readable stand-in for a subquery.

WITH high_earners AS (
  SELECT employee, department, salary
  FROM employees
  WHERE salary > 100000
)
SELECT department, COUNT(*) AS num_high_earners
FROM high_earners
GROUP BY department;

Why CTE Over Subquery

  • Readability — breaks nested queries into named, sequential steps
  • Reusable within the same query — reference it multiple times without repeating logic
  • Chainable — each CTE can build on the previous one
WITH regional_sales AS (
  SELECT region, SUM(amount) AS total_sales
  FROM sales
  GROUP BY region
),
top_regions AS (
  SELECT region
  FROM regional_sales
  WHERE total_sales > 1000000
)
SELECT * FROM sales
WHERE region IN (SELECT region FROM top_regions);
Materialization varies by engine: Postgres (modern)/SQL Server may inline a CTE like a subquery. MySQL and older Postgres always materialize (compute once, reuse) — matters for performance when a CTE is referenced multiple times. Check your engine.

Recursive CTEs

WITH RECURSIVE — a CTE that references itself. Used for hierarchies/graphs (org charts, category trees, graph traversal).

WITH RECURSIVE org_chart AS (
  -- Base case: top of the hierarchy
  SELECT employee_id, name, manager_id, 1 AS depth
  FROM employees
  WHERE manager_id IS NULL

  UNION ALL

  -- Recursive case: joins back to the CTE itself
  SELECT e.employee_id, e.name, e.manager_id, oc.depth + 1
  FROM employees e
  JOIN org_chart oc ON e.manager_id = oc.employee_id
)
SELECT * FROM org_chart ORDER BY depth;

Execution model

  1. Run the base case → first batch of rows
  2. Run the recursive case using only the previous step's new rows — not the whole accumulated result
  3. Repeat, feeding each new batch back in, until the recursive case returns zero rows
  4. Union everything together

Key detail: it's iterative on the newest batch, not a full re-scan each time.

Guardrail: the recursive case needs a terminating condition (e.g. manager_id IS NULL running out) or it loops infinitely. Some engines support LIMIT or a max-recursion-depth safety net.
