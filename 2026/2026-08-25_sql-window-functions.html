PARTITION BY

GROUP BY without collapsing rows — every row stays, annotated with its group value.

AVG(salary) OVER (PARTITION BY department) AS dept_avg

Ranking Functions

FunctionTies
ROW_NUMBER()Always unique: 1,2,3,4…
RANK()Shared rank, gaps after: 1,2,2,4
DENSE_RANK()Shared rank, no gaps: 1,2,2,3
ROW_NUMBER() OVER (ORDER BY score DESC) AS rn
RANK()       OVER (ORDER BY score DESC) AS rnk
DENSE_RANK() OVER (ORDER BY score DESC) AS drnk

Offset — LAG / LEAD

Value from another row, per the ORDER BY in OVER(). LAG = previous, LEAD = next.

LAG(revenue) OVER (ORDER BY date) AS prev_day
LAG(revenue, 7, 0)  -- 7 rows back, default 0 if none

Aggregates as Windows

SUM/AVG/etc., non-collapsing. Pair with a frame for running totals or rolling averages.

SUM(revenue) OVER (ORDER BY date) AS running_total
AVG(revenue) OVER (
  ORDER BY date ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
) AS rolling_7day_avg

Distribution Functions

  • NTILE(4) — splits rows into 4 equal buckets (quartiles)
  • PERCENT_RANK() — relative rank as a fraction (0–1)
  • FIRST_VALUE() / LAST_VALUE() — first/last in the window frame
FIRST_VALUE(employee) OVER (
  PARTITION BY department ORDER BY salary DESC
  ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
) AS top_earner

Frame Clause — Why It's Needed

Default frame when ORDER BY is used: RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW — start of partition through the current row only, not the whole partition.

Breaks LAST_VALUE(): its frame ends at the current row, so "last value" = the row's own value, every time. FIRST_VALUE() is unaffected since the first row never changes.

Fix: ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING — spans the full partition.

Rule of thumb: default frame → correct for running/rolling calcs. Fixed reference point (e.g. "top earner") → override the frame, or use MAX()/MIN() instead.
