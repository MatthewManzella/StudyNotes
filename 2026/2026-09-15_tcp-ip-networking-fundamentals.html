TCP/IP stack overview

Four layers, each wraps the layer above in its own header (encapsulation): Link → Internet (IP) → Transport (TCP/UDP) → Application (HTTP, DNS, TLS, gRPC).

Ethernet frame [ IP packet [ TCP segment [ HTTP data ] ] ]

IP: addressing and routing

Every device gets an IP address; routers forward packets hop by hop. IP is "best effort" — no guarantee of arrival, order, or uniqueness.

VersionAddress space
IPv4~4.3 billion (essentially exhausted)
IPv62^128 (not a practical concern)

Public addresses are globally routable; private addresses (192.168.x.x, 10.x.x.x) are local-network only. NAT lets many devices share one public IP. TTL is decremented at each router hop and drops the packet at zero — prevents infinite loops, also what traceroute exploits to map a path.

Ports and sockets

A port (0–65535) routes traffic to a specific program on a machine. A socket is the tuple {source IP, source port, destination IP, destination port}.

Common well-known ports: 80 (HTTP), 443 (HTTPS), 53 (DNS), 22 (SSH).

TCP three-way handshake

Client and server agree on starting sequence numbers before any data flows.

Client → SYN
Server → SYN-ACK
Client → ACK
(connection established)

Sequence numbers and acknowledgments

Every byte is numbered; receiver ACKs "got everything through byte N." Missing ACK within timeout → sender retransmits. Numbering also lets the receiver reorder out-of-sequence packets.

Flow control (sliding window)

Receiver advertises a window size — max unacknowledged bytes it'll buffer — so a fast sender can't overwhelm a slow receiver.

Congestion control

Protects the network, not just the receiver: "slow start" ramps up sending rate while ACKs arrive cleanly, then cuts sharply on detected loss and ramps back up more conservatively.

This is why a transfer speeds up over the first second or two, and why one congested link slows down every connection sharing it.

UDP vs TCP

UDP skips the handshake, sequencing, retransmission, and windowing entirely — just sends the packet. Lower overhead, no reliability guarantee.

Use caseWhy UDP
Video callsA late retransmit is worse than a dropped frame
DNSSpeed matters more than reliability; falls back to TCP only for large responses
